# 业务模块工程结构：如何新建一个业务模块

wen-saas 后端是「模块化单体」：底座（core）提供多租户、认证、权限、自定义字段等基础能力，业务功能以独立 Maven 模块的形式挂在 `modules/` 下，通过 SPI 在启动期向底座注册。本文以仓库内可运行的样板模块 `modules/module-crm_demo/` 为例，讲清新建一个业务模块的完整步骤。

## 一、工程总体结构

```
wen-saas-boot/
├── core/
│   ├── core-api/        扩展点接口与模型（业务模块面向它编程）
│   ├── core-impl/       底座实现
│   └── core-web/        底座 Web 层（分页、异常、JSON 序列化等公共件）
├── modules/             业务模块聚合（packaging=pom）
│   └── module-crm_demo/ 样板：CRM 客户管理 Demo
└── app/                 启动器；它的依赖列表决定本次部署包含哪些模块
```

新建模块要动三处：

1. `modules/module-{code}/`：新建 Maven 子工程；
2. `modules/pom.xml`：`<modules>` 中追加 `<module>module-{code}</module>`；
3. `app/pom.xml`：`<dependencies>` 中追加该模块依赖——**app 的依赖列表就是部署清单**，想下线某模块，从 app 依赖里移除后重新打包即可。

## 二、模块目录与坐标约定

以 `crm_demo` 为例（`{code}` 是模块编码，规则：小写字母开头，仅含小写字母/数字/下划线）：

```
modules/module-crm_demo/
├── pom.xml
└── src/main/
    ├── java/com/wensaas/crmdemo/
    │   ├── spi/CrmDemoModule.java          # BusinessModuleDescriptor 实现（模块入口）
    │   ├── controller/                     # REST 控制器
    │   ├── service/                        # 业务服务
    │   ├── repository/                     # MyBatis-Plus Mapper
    │   ├── entity/                         # 实体（@TableName）
    │   └── namesource/                     # id→显示名解析声明（可选）
    └── resources/db/migration/crm_demo/    # Flyway 迁移脚本，独占子目录 = 模块 code
        └── V1.0.0__init_crm_demo.sql
```

pom 关键点：parent 指向 `wen-saas-boot-modules`，artifactId 约定 `wen-saas-boot-module-{code}`（下划线转连字符），依赖底座 Web 层即可间接拉入 core-api / core-impl / MyBatis-Plus：

```xml
<parent>
    <groupId>com.wensaas</groupId>
    <artifactId>wen-saas-boot-modules</artifactId>
    <version>0.9.1</version>
</parent>

<artifactId>wen-saas-boot-module-crm-demo</artifactId>

<dependencies>
    <dependency>
        <groupId>com.wensaas</groupId>
        <artifactId>wen-saas-boot-core-web</artifactId>
    </dependency>
    <!-- 按需：lombok / spring-boot-starter-validation / springdoc-openapi-starter-webmvc-api -->
</dependencies>
```

## 三、SPI 注册：BusinessModuleDescriptor

模块入口是一个实现 `com.wensaas.core.api.spi.BusinessModuleDescriptor` 的类，加 `@BusinessModule` 注解（语义等同 `@Component`，由 Spring 扫描收集）。底座启动时收集所有该接口的 Bean，依次校验并注册——不需要 `META-INF/services` 文件。

`crm_demo` 的真实实现（节选）：

```java
@BusinessModule
public class CrmDemoModule implements BusinessModuleDescriptor {

    @Override
    public ModuleMetadata metadata() {
        return new ModuleMetadata(
                "crm_demo",                 // code：全局唯一，[a-z][a-z0-9_]*
                "客户管理 Demo",             // name
                "覆盖底座全部集成能力的官方样板业务模块，各项能力接入均可对照参考",  // description
                "1.0.0",                    // version：语义化版本
                null,                       // icon
                List.of());                 // dependencies：依赖的其他模块 code
    }

    @Override
    public List<String> apiPathPrefixes() {
        return List.of("/api/v1/biz/crm_demo/");
    }

    @Override
    public List<PermissionDef> permissions() {
        return List.of(
                new PermissionDef("crm_demo.customer.view", "客户 · 查看", "「我的客户」视图与客户详情"),
                new PermissionDef("crm_demo.customer.view_manage", "客户 · 管理视图", "「客户管理」全量列表与导出"),
                new PermissionDef("crm_demo.customer.edit", "客户 · 编辑", "新增 / 编辑 / 删除客户、推进状态"));
    }

    @Override
    public List<CustomFieldObjectDef> customFieldObjects() {
        return List.of(new CustomFieldObjectDef(
                "crm_demo.customer", "crm_demo_customer", "extra", "客户自定义字段"));
    }

    @Override
    public List<DataPermissionTableDef> dataPermissionTables() {
        return List.of(new DataPermissionTableDef(
                "crm_demo.customer", "客户", "crm_demo_customer", "owner_id", "owner_dept_id"));
    }
}
```

接口的扩展点全部有 default 空实现，**按需覆盖**：`permissions()`（权限点）、`dictGroups()`（字典分组）、`dashboardCards()`（工作台卡片）、`h5Pages()`（H5 页面）、`notificationTemplates()`（通知模板）、`importEntities()`（数据导入）、`eventSubscriptions()`（平台事件订阅）、`customFieldObjects()`（自定义字段宿主对象）、`dataPermissionTables()`（数据权限参与表）、`taskHandlers()`（任务处理器）、`packages()`（预置套餐包）。各扩展点的声明类（`DictGroupDef`、`DashboardCardDef`、`H5PageDef`、`EventSubscription`、`PackageDef` 等）都在 `core-api` 的 `com.wensaas.core.api.spi.def` 包，类上的 javadoc 即字段级接入说明；权限点、自定义字段、任务、导入、通知模板另有专篇（见 README 索引）。

两点注意：

- **API 前缀**：`apiPathPrefixes()` 默认 `/api/v1/{code}/`；推荐照样板显式声明为 `/api/v1/biz/{code}/`，与底座保留前缀（`/api/v1/base`、`/api/v1/ops`、`/api/v1/me` 等）明确区隔。该前缀会注册到 `ModuleApiRouteRegistry`，由 `PackageStatusWebFilter` 按租户套餐拦截：未购买返 402 `PACKAGE_UNAUTHORIZED`，套餐过期时写请求返 403 `PACKAGE_READONLY`——业务代码无需自行判断套餐状态。
- **菜单不走 SPI**：菜单树以 `sys_menu` 表为唯一权威，模块菜单通过底座迁移脚本或菜单管理页录入，`permission_code` 关联 SPI 声明的权限点。

### 预置套餐包：packages()

模块可以声明自带的套餐包，实现开箱即用——装上模块启动一次，运营无需手工建包即可把套餐授予租户：

```java
@Override
public List<PackageDef> packages() {
    return List.of(PackageDef.of(
            "crm_demo.starter", "客户管理 Demo 入门包",
            "开通即含客户管理全部功能"));  // 描述面向运营/租户可读，写清套餐实际包含什么
}
```

规则与语义：

- **命名空间**：套餐编码按 `{code}.{pkg_name}` 命名（如 `crm_demo.starter`），启动期校验全局唯一与前缀归属；
- **隐含包含自身**：`PackageDef.moduleCodes` 是"额外包含的模块"（可跨模块引用打组合包），落库时自动并入声明模块自己，入门包传空列表即可；引用不存在或未启用的模块会阻断启动；
- **insert-if-missing**：编码不存在才插入（默认插入即上架，`publishOnCreate=false` 可改为草稿）；已存在则整行跳过——套餐落库后归运营维护，运营在套餐管理页的改名 / 调模块集 / 上下架 / 归档在重启后原样保留；
- **不可物理删除**：模块声明的套餐（列表里带"模块预置"标记）不允许删除，否则重启会被重新插入而"复活"；要下线走下架 / 归档（归档后不会再重建）。

### 启动期注册流程

```
收集所有 BusinessModuleDescriptor Bean
→ 过滤禁用模块（wen-saas-boot.business-modules.enabled.{code}=false，默认启用）
→ NamespaceValidator 命名空间校验（冲突一次性收集，抛 BusinessModuleConflictException 阻断启动）
→ 按 metadata().dependencies() 拓扑排序（循环依赖 / 依赖缺失非法）
→ ModuleSchemaMigrator 逐模块跑 Flyway 迁移
→ ModuleTableValidator 表归属与存在性校验
→ 各注册表注册（权限点 / 字典 / 卡片 / ...）
→ BusinessModuleDbSynchronizer 同步 sys_business_module（版本升降级仅记日志，不阻断）
→ PackageSpiSynchronizer 同步预置套餐 sys_package / sys_package_module（insert-if-missing）
```

## 四、命名空间约定

所有编码必须落在模块自己的命名空间内，启动期强校验（既查全局唯一、又查前缀归属）：

| 对象 | 规则 | 例子 |
|---|---|---|
| 模块编码 | `[a-z][a-z0-9_]*`，全局唯一 | `crm_demo` |
| 权限点 / 字典 / 通知模板 / 工作台卡片 / 预置套餐编码 | `{code}.` 前缀 | `crm_demo.customer.view` |
| H5 路由 | `{code}/` 前缀 | `crm_demo/customers` |
| 物理表名 | `{code}_` 前缀（`sys_` 为底座保留） | `crm_demo_customer` |
| API 路径 | `apiPathPrefixes()` 声明，跨模块不得重复 | `/api/v1/biz/crm_demo/` |

表归属校验不需要手工声明表清单：底座扫描所有 MyBatis-Plus `BaseMapper` 的 entity 泛型，读 `@TableName`，要求表名前缀匹配到某个已启用模块，且表真实存在于数据库。

## 五、数据库迁移文件放哪

- 位置：`src/main/resources/db/migration/{code}/`（独占子目录，目录名必须等于模块 code）；
- 命名：`V{major}.{minor}.{patch}__{description}.sql`，版本号**仅在本模块内**唯一、从 `V1.0.0` 起递增，与底座和其他模块互不相干，无需全局协调；
- 执行：每个模块独占一条 Flyway 版本线，history 表为 `flyway_history_{code}`，由 `ModuleSchemaMigrator` 在底座迁移之后、按模块拓扑序执行；模块没有脚本则跳过；
- 前向兼容：允许加表、加字段、加索引；禁止删字段、改字段类型（回滚只回滚 jar，schema 不自动回滚）。

建表规范（摘自 `V1.0.0__init_crm_demo.sql`）：

```sql
CREATE TABLE crm_demo_customer (
    id            BIGINT       NOT NULL PRIMARY KEY,   -- 雪花 ID，应用层生成
    tenant_id     BIGINT       NOT NULL DEFAULT 0,     -- 多租户隔离列
    name          VARCHAR(255) NOT NULL,
    status        VARCHAR(20)  NOT NULL DEFAULT 'LEAD',
    creator_id    BIGINT       NOT NULL,               -- 创建人（非行级归属锚点）
    owner_id      BIGINT,                              -- 负责人，数据权限 SELF 列
    owner_dept_id BIGINT,                              -- 归属部门，数据权限 部门 列
    extra         JSONB,                               -- 自定义字段容器
    created_at    TIMESTAMP    NOT NULL,
    updated_at    TIMESTAMP    NOT NULL,
    deleted_at    TIMESTAMP                            -- 软删标记，NULL = 未删
);

-- 索引前缀必须 tenant_id；活跃行用 partial index 跳过软删行
CREATE INDEX idx_crm_demo_customer_tenant_status
    ON crm_demo_customer (tenant_id, status) WHERE deleted_at IS NULL;
```

对应实体挂 MyBatis-Plus 注解即可接入底座各拦截器：

```java
@TableName(value = "crm_demo_customer", autoResultMap = true)
@CustomFieldExtension(objectCode = "crm_demo.customer")   // 接入自定义字段框架（可选）
public class CrmDemoCustomer {
    @TableId(type = IdType.ASSIGN_ID)                     // 雪花 ID
    private Long id;
    private Long tenantId;                                // 由多租户拦截器自动注入
    @TableField(typeHandler = JacksonTypeHandler.class)
    private Map<String, Object> extra;
    @TableLogic(value = "null", delval = "now()")         // 软删
    private LocalDateTime deletedAt;
    // ...
}
```

## 六、新建模块检查清单

1. `modules/module-{code}/` 建工程，parent 指 `wen-saas-boot-modules`，依赖 `wen-saas-boot-core-web`；
2. `modules/pom.xml` 加 `<module>`，`app/pom.xml` 加依赖；
3. 写 `{Code}Module implements BusinessModuleDescriptor` + `@BusinessModule`，声明 metadata / apiPathPrefixes / permissions 等；
4. `db/migration/{code}/V1.0.0__init_{code}.sql` 建表（表名 `{code}_` 前缀、tenant_id、软删、索引规范）；
5. Controller 路径落在 `apiPathPrefixes()` 声明的前缀下，方法挂 `@RequirePermission`（权限点即 SPI 声明的 code）；
6. 菜单入 `sys_menu`；
7. 启动应用——命名冲突、表归属、迁移问题都会在启动期报错阻断，按错误信息修正即可。

遇到拿不准的写法，直接对照 `modules/module-crm_demo/` 抄：它就是为此存在的可运行样板。
