# 自定义字段接入

自定义字段框架让租户能在业务实体上自助加字段（文本 / 数字 / 日期 / 枚举 / 引用……），而业务模块**不改表、不发版**。原理：实体表带一个 jsonb 容器列 `extra`，字段定义是租户级元数据，写入校验、查询重写、展示翻译全部由底座的 MyBatis-Plus 拦截器和解析器自动完成。业务模块的接入成本只有三处声明。

## 一、实体侧要做什么

### 1. 建表：加一列 `extra JSONB`

```sql
CREATE TABLE crm_demo_customer (
    id            BIGINT       NOT NULL PRIMARY KEY,
    tenant_id     BIGINT       NOT NULL DEFAULT 0,
    name          VARCHAR(255) NOT NULL,
    -- ...业务标准列...
    extra         JSONB,                     -- 自定义字段值容器，key 为 cf_ 前缀字段编码
    created_at    TIMESTAMP    NOT NULL,
    updated_at    TIMESTAMP    NOT NULL,
    deleted_at    TIMESTAMP
);
```

不要预建 `extra` 的任何索引——字段被租户"索引化"时，框架会按需创建 `(tenant_id, (extra->>'cf_xxx'))` 表达式索引（所以表必须有 `tenant_id` 列）。

### 2. 实体：三个注解缺一不可

```java
@TableName(value = "crm_demo_customer", autoResultMap = true)   // jsonb ↔ Map 转换依赖 autoResultMap
@CustomFieldExtension(objectCode = "crm_demo.customer")          // 声明宿主对象 code
public class CrmDemoCustomer {
    // ...标准字段...

    /** 自定义字段 jsonb 容器。 */
    @TableField(typeHandler = JacksonTypeHandler.class)
    private Map<String, Object> extra;
}
```

`@CustomFieldExtension`（`com.wensaas.core.api.customfield.CustomFieldExtension`）的 `extraField` 默认就叫 `extra`，一般不用改。容器字段类型必须是 `Map<String, Object>`——框架启动后首次触达时反射校验，不满足直接抛 `IllegalStateException`。

### 3. 注册实体类型

在模块入口 `BusinessModuleDescriptor.customFieldObjects()` 声明宿主对象：

```java
@Override
public List<CustomFieldObjectDef> customFieldObjects() {
    return List.of(new CustomFieldObjectDef(
            "crm_demo.customer",    // code：与 @CustomFieldExtension.objectCode 一致
            "crm_demo_customer",    // 物理表名（查询重写按表名反查对象）
            "extra",                // jsonb 列名
            "客户自定义字段"));
}
```

**code 三处必须一致**：`@CustomFieldExtension.objectCode` == `CustomFieldObjectDef.code` == 名称解析框架（NameLookup）里注册的实体类型。对象的中文显示名、以及本对象被别人 REF 引用时的名称翻译，都来自同一个 `NameLookup` Bean（用 `NameSourceFactory` 一行注册，见 [实体名称解析](10-实体名称解析.md)），所以想让对象能被 REF 字段引用，把这个 Bean 也配上。

## 二、写入：校验自动生效

业务代码只管把前端传来的自定义字段值原样塞进 `extra`，然后普通 `mapper.insert / updateById`：

```java
r.setExtra(request.custom());   // Map<String,Object>，key 形如 "cf_industry"
mapper.insert(r);               // CustomFieldWriteInterceptor 自动校验
```

拦截器（`CustomFieldWriteInterceptor`）在 INSERT / UPDATE 前按租户的字段定义校验：

- **必填**：`required=true` 的字段缺失或为 null 报错（`extra` 整体为空也会因必填缺失报错）；
- **类型**：文本必须 String（≤255，长文本 ≤4000）、数字必须 Number、布尔必须 Boolean、日期收 ISO-8601 字符串或日期类型、枚举必须是所关联字典分组内的项 code、引用必须是目标对象的 ID（数字或纯数字字符串）；
- **未声明的 key 不报错也不剔除**——会原样写进 jsonb，前端别乱传。

校验失败抛 `CustomFieldException`，走全局异常映射，业务代码不用 catch。

## 三、查询与筛选：写普通条件即可

**收集筛选参数**：Controller 层把 `cf_` 前缀的 query 参数注入 `Map` 用 `@CustomFieldEquals`（`com.wensaas.core.web.customfield`），底座自动摘出全部 `cf_` 前缀且非空白的项，参数永不为 null，也不进 OpenAPI 文档（`cf_*` 是租户级动态列，接口描述里文字说明即可）：

```java
@GetMapping
public PageResult list(@RequestParam(required = false) String status,
                       @CustomFieldEquals Map<String, Object> cfEquals, ...) {
    return service.page(new Query(status, ..., cfEquals));
}
```

**拼查询条件**：把 `cf_` 键当普通列名交给 `QueryWrapper`，重写器会接管——键是**运行时值**（来自上面 `@CustomFieldEquals` 收集的筛选 `Map`、或前端传入的排序列名），业务代码不写死某个具体字段名（各租户配的字段不同，见 §五反模式）；等值 `eq`、排序 `orderBy` 等条件照常拼：

```java
QueryWrapper<CrmDemoCustomer> w = new QueryWrapper<>();
query.cfEquals().forEach(w::eq);   // 键已由 @CustomFieldEquals 保证 cf_ 前缀且非空
Page<CrmDemoCustomer> page = mapper.selectPage(new Page<>(pageNo, size), w);
```

查询重写器（`CustomFieldQueryRewriter`）在 SQL 执行前把 WHERE / ORDER BY / GROUP BY / HAVING 里的 `cf_xxx` 列引用改写为 `extra->>'cf_xxx'`，并做两条硬校验：

- 字段未定义 → `FIELD_NOT_FOUND`；
- 字段**未索引化** → `UNINDEXED_QUERY_NOT_ALLOWED`（防 jsonb 全表扫，租户想按某字段筛选，先在字段管理页开启索引）。

它与租户隔离、数据权限在同一条拦截器链上自动叠加，业务代码依旧零感知。

### 展示翻译（枚举 / 引用补显示名）

枚举存的是字典项 code、引用存的是目标 ID，返回前端前用 `CustomFieldDisplayResolver`（core-api 接口）批量补 `__label`：

```java
List<Map<String, Object>> views =
        displayResolver.resolveViews("crm_demo.customer", extras);  // 列表，批量翻译防 N+1
Map<String, Object> view = displayResolver.resolveView(entity);      // 详情，单 entity
```

输出在原值旁多出 `cf_xxx__label` 键（枚举查字典、引用走名称解析框架）；翻不出来的值不加 label，前端按原值兜底展示。

## 四、字段定义管理归谁

**归租户端配置，业务模块不需要写任何字段管理代码。** 底座提供统一端点 `/api/v1/base/custom-fields`（对象列表、字段增删改名、索引化开关、额度查询），权限点 `custom_field.view` / `custom_field.manage`。租户管理员在设置页对任意已注册对象加字段，业务模块的表和代码不用动。

字段类型（创建后**类型不可修改**，只能改显示名）：

| 类型 | code | 说明 |
|---|---|---|
| 单行文本 | `text` | ≤255 字符 |
| 多行文本 | `long_text` | ≤4000 字符 |
| 数字 | `number` | |
| 日期 | `date` | |
| 布尔 | `bool` | |
| 枚举 | `enum` | 关联一个字典分组，值 = 字典项 code |
| 引用 | `ref` | 关联另一个已注册对象，值 = 目标 ID |

**REF 的"关联对象"候选从哪来**——`GET /api/v1/base/custom-fields/ref-objects`：

- 单一来源：名称解析框架（[实体名称解析](10-实体名称解析.md)）里注册的、且 `tenantSearchable && referenceable` 都为 true 的实体类型——**不是** `customFieldObjects()` 注册表，也不另维护白名单；
- 成员 / 部门等系统实体底座已注册；业务对象按 §一.3 末尾说明注册同 code 的名称源后自动进入候选；
- 角色这类权限构件注册时 `referenceable=false`，能被搜索（如审计按对象筛选）但不出现在 REF 候选里；
- 创建 REF 字段时后端按同一规则校验 `refObjectCode`；表单里选具体记录的下拉搜索也由同一名称源的 `NameSearch` 提供。

其他内置约束：字段编码强制 `cf_` 前缀且须是合法小写标识符；额度按**租户**计、全部对象共享（不按对象分摊），默认 **20 个字段 / 5 个索引**（原子扣减，超限报错；默认值可通过配置调整）；删字段是软删（jsonb 里的历史值保留，90 天后由内置定时任务摘除 key 并真删定义；关闭定时任务（`wen-saas-boot.jobs.enabled=false`）的部署这项清理不会执行）。

## 五、约束与反模式

- **不要手写 `extra->>'cf_xxx'` SQL**——绕过了"未索引化禁查"防线和字段存在性校验；统一走 `cf_` 列名让重写器接管；
- **不要用自定义字段承载业务核心逻辑**：框架不保证引用完整性（REF 目标被删不级联、不报错），需要强约束的关系建实体表和外键列；
- **不要在业务代码里预设某个 `cf_` 字段存在**——字段是租户自助配的，各租户不同；业务逻辑只依赖标准列，自定义字段做透传与展示；
- **字段默认值只是元数据**：`defaultValue` 当前不做写入自动填充，别依赖它；
- **`@CrossTenantQuery` 链路上校验与重写同步失效**（自定义字段定义按租户隔离，跨租户语境下无从裁决）——又一个业务模块禁用跨租户查询的理由；
- 排查时记住拦截器链顺序：租户隔离 → 数据权限 → 自定义字段查询重写 → 写入校验 → 分页。自定义字段重写在租户过滤之后，永远只看得到当前租户的字段定义。

## 六、接入检查清单

1. 建表加 `extra JSONB`（表必须有 `tenant_id`），不建 extra 索引；
2. 实体：`autoResultMap = true` + `@CustomFieldExtension(objectCode)` + `Map<String,Object> extra` 挂 `JacksonTypeHandler`；
3. 模块入口 `customFieldObjects()` 注册 `CustomFieldObjectDef`，code 三处一致；
4. （可选）注册同 code 的 `NameLookup`（[实体名称解析](10-实体名称解析.md)），让对象可被 REF 引用、显示名可翻译；
5. 写入直接 `setExtra` + insert/update；查询用 `cf_` 列名拼条件；返回前端前过一遍 `CustomFieldDisplayResolver`；
6. 验证：在租户设置页给对象加一个必填字段 + 一个索引化字段，走一遍创建（必填拦截）、筛选（索引化字段可查、未索引化报错）、列表展示（`__label` 补齐）。
