# 操作日志接入

底座把日志拆成三类，靠 `requestId + 操作人` 串联；业务模块只需要关心其中两类的接入：

| | 落点 | 业务模块要做什么 |
|---|---|---|
| ① 请求/响应日志 | 日志文件（内部排障） | 无需接入，Filter 自动记录修改型请求与错误响应 |
| ② 审计日志（操作记录） | `sys_operation_log` | 在写操作方法上加 `@Auditable` |
| ③ 数据变更日志（字段级 diff） | `sys_data_change_log`（PG 触发器） | 在 Flyway 迁移里为业务表登记列元数据 + 挂触发器 |

② 记"谁做了什么操作"，③ 记"哪张表哪个字段从什么改成什么"，二者按 `requestId` 关联——操作记录详情页可展开同一请求下的逐字段变更。

## 一、`@Auditable`：一请求一行审计

在 Controller 方法上声明（`core-api` 的 `audit` 包），由切面拦截写入，经 RocketMQ 异步批量落库，不拖慢主链路：

```java
@Auditable(module = "crm_demo", action = "新建客户", objectType = "crm_demo.customer",
           objectIdExpr = "#result.id", objectDescExpr = "#result.name")
public Customer createCustomer(CustomerCreateRequest request) { ... }
```

### action 直接写中文

`action` 是自由字符串、无后端枚举，**直接写中文短语**，前端原样展示不做翻译。要求「动词 + 对象」自描述：写 `新建角色` / `编辑部门` / `停用成员` / `提交工单`，**不写裸「新建 / 更新 / 删除」**（光看操作类型列即知发生了什么）。前端按关键词上色，措辞需保留命中词：含「新建/启用/激活/分配」→ 绿，「删除/停用/重置/解绑/移除」→ 红，「代登录/暂停/强制」→ 橙，「更新/修改/编辑/切换/调整/权限」→ 蓝。

### objectType 必须是实体 code

`objectType` 只能填**名称解析框架里已注册的实体 code**或留空。底座内建实体用 `EntityTypes` 常量（`core-api` 的 `namesource` 包，如 `EntityTypes.SYS_USER` = `"sys.user"`）；**业务模块的实体填自己的 code**（如 `"crm_demo.customer"`），前提是已为它注册名称源——见 [实体名称解析](10-实体名称解析.md)。启动期 `AuditObjectTypeValidator` 会扫描所有 `@Auditable`，发现非法值（中文、未注册 code）直接 fail-fast 阻断启动。对象类型的中文列名由读取侧按 code 派生；没有对应实体的操作（如"修改密码"的附属动作）留空，语义由 action 承载。

### 其余注解属性

- `objectIdExpr` / `objectDescExpr`：SpEL，可引用方法参数名（`#request`）与返回值（`#result`），如 `"#result.id"`；为空则对应列留 null。
- `recordRead`：默认 `false`——**普通读操作不记录，只记写操作**；仅显式声明的"敏感读"（如导出、明文查看）才设 `true`。
- `targetTenantIdExpr`：运营端对某租户操作时填（如 `"#tenantId"`），落 `target_tenant_id` 支持"运营查自己的操作、租户查发生在自己身上的操作"双向检索。

### 多主对象：`AuditObjects.add`

一个请求操作多个主对象（批量、导入逐行）时，在 service 里逐个登记，切面收尾合并进**同一行**审计的 `object_refs`（JSONB + GIN 索引，支持按对象 id 追溯）：

```java
AuditObjects.add(EntityTypes.SYS_USER, String.valueOf(userId), user.getRealName());
// 改名场景可用四参重载表达"旧名/新名"
AuditObjects.add(EntityTypes.SYS_DEPT, String.valueOf(deptId), "财务部", "财务一部");
```

纪律：只在业务事件真正涉及多对象时登记；单对象场景不用调，写入侧会从注解的 objectType / objectId / objectDesc 自动派生。单请求上限 500 条防止撑爆一行。

### 失败操作的状态自动回填

方法抛异常时同样会记一行（`error_message` = 异常消息）。此时最终 HTTP 状态还没产生（异常尚未到达异常处理器），事件先被暂存，由 `PendingAuditFlushFilter` 在响应提交后读取真实的 `response.getStatus()` 回填再落库——业务拒绝会如实记成 422 / 409 而不是一律 500。业务代码无需做任何事，**不要**自己在切面或 service 里写死状态码。

### 手动记录（少数场景）

极少数拿不到注解上下文的场景（如登出后置动作、后台任务）可注入 `AuditLogRecorder` 直接 `record(AuditEvent)`。优先用注解，手动记录是逃生口。

## 二、什么该记、什么不该记

- **写操作（POST / PUT / PATCH / DELETE）都应有 `@Auditable`**；一个业务动作一行，不要在内部子步骤重复记。
- **普通读不记**；敏感读（导出、明文 reveal）显式 `recordRead = true`。
- **字段级"改前/改后"不归 ②**：`@Auditable` 不捕获参数与返回值 diff，值变更由 ③ 触发器免费记录，别在审计里手工拼 diff。
- 接口设计上优先"动词化端点"（启用 / 禁用 / 重置各自一个端点），action 天然自描述；一把改多字段的编辑端点用宽泛 action（如"编辑客户资料"），细节靠 ③ 补。

## 三、数据变更日志：业务表纳入 PG 触发器

③ 由一个共用触发器函数 `sys_audit_row_change()` 在业务事务内同步写 `sys_data_change_log`，与数据变更原子一致；操作上下文（requestId / 操作人 / 租户）由框架经事务级 GUC 自动注入，触发器自取，业务代码零感知。软删除（`UPDATE deleted_at`）会被归一为 DELETE 语义。

范围是**声明式 allowlist**：想让某张业务表的变更进 ③，在模块自己的 Flyway 迁移里做两件事——

```sql
-- 1) 登记列元数据：'*' 行代表整表纳入，其余行做列级覆盖
INSERT INTO sys_audit_table_config(table_name, column_name, label, render) VALUES
    ('crm_demo_customer', '*',       NULL,       'SCALAR'),
    ('crm_demo_customer', 'name',    '客户名称', 'SCALAR'),
    ('crm_demo_customer', 'status',  '状态',     'ENUM:customerStatus'),  -- 按字典译"1→启用"
    ('crm_demo_customer', 'id_card', '证件号',   'MASK'),                 -- 敏感列只记 "<已变更>" 占位
    ('crm_demo_customer', 'sync_at', NULL,       'EXCLUDE');              -- 噪声列不出现在 diff

-- 2) 挂共用触发器
CREATE TRIGGER trg_audit_crm_demo_customer
    AFTER INSERT OR UPDATE OR DELETE ON crm_demo_customer
    FOR EACH ROW EXECUTE FUNCTION sys_audit_row_change();
```

`render` 决定"怎么记 + 前端怎么译"，取值：

| render | 含义 |
|---|---|
| `SCALAR` | 记真实 before/after，原样展示 |
| `ENUM:dictCode` | 记原始值，展示时按字典编码翻译成中文 |
| `REF:entityType` | 外键列，展示时按实体类型反查名称 |
| `MASK` | 感知到变化但只写 `"<已变更>"` 占位，不落敏感值（密文 / 密钥列必用） |
| `EXCLUDE` | 不进 diff（如冗余时间戳等噪声列） |

注意事项：

- `created_at / created_by / updated_at / updated_by / deleted_at / version` 已全局排除，无需逐表登记。
- 密文列（确定性加密）比较仍然成立不会误报，但必须标 `MASK` 防止密文泄漏进日志。
- 触发器整行无字段变化时不落记录；**严禁**把日志表自身挂上触发器（防递归）。
- "用户 A 把 B 从 X 改成 Y"是展示层按 `label` / `render` 拼出的视图，库里只存原始 diff——列元数据配得越全，操作记录详情页越可读。
