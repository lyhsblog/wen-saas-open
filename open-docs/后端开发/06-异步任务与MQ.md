# 异步任务与 MQ

耗时操作（导入、导出、批量处理）不要占着 HTTP 请求线程跑，接**任务中心**：提交后立刻返回 taskId，执行走 MQ 异步化，进度、取消、结果下载、终态通知都由底座统一提供。需要订阅消息的场景则直接写 RocketMQ 消费者，底座对重试、死信、幂等有一套固定约定。

## 一、任务中心：定义并注册一个任务

### 1. 实现 TaskHandler

业务模块实现 `com.wensaas.core.api.task.TaskHandler`，注册为 Spring Bean（`@Component`）：

```java
@Component
public class CrmCustomerImportHandler implements TaskHandler {

    @Override
    public String handlerCode() {
        return "crm_demo.task.import.customer";   // 模块命名空间前缀 + ".task." + 业务标识
    }

    @Override
    public void execute(TaskContext context) {
        List<Row> rows = loadRows(context.params());
        context.setTotal(rows.size());
        int processed = 0;
        for (Row row : rows) {
            if (context.isCancelled()) return;    // 优雅响应取消，框架落 CANCELLED
            try {
                importOne(row);
                context.recordSuccess(1);
            } catch (BizRowException e) {
                context.recordFailure(1);
            }
            context.updateProgress(++processed * 100 / rows.size(), processed);
        }
        context.setResult(Map.of("imported", processed));
    }
}
```

契约：`execute` 正常返回 → 任务自动置 `COMPLETED`；抛 `RuntimeException` → 自动置 `FAILED`（异常 message 落 `errorMessage`，截断 4000 字符）——**不要吞异常再手工标状态**。

### 2. 在模块入口声明

任务处理器通过 `BusinessModuleDescriptor.taskHandlers()` 显式注册（不是注解扫描）：

```java
@Override
public List<TaskHandlerDef> taskHandlers() {
    return List.of(new TaskHandlerDef("crm_demo.task.import.customer",
                                      CrmCustomerImportHandler.class));
}
```

### 3. 提交任务

注入 `com.wensaas.core.api.task.TaskService`：

```java
Long taskId = taskService.submit(new SubmitRequest(
        TaskType.IMPORT,                     // IMPORT / EXPORT / BATCH / OTHER
        "客户导入",
        "crm_demo.task.import.customer",
        Map.of("fileId", fileId)));          // params：必须可 JSON 序列化，执行侧从 context.params() 取
```

提交语义：落 `sys_task` 表 → **事务提交后**投递执行消息（发送失败不回滚，由补偿巡检重投，任务最多短暂停留 PENDING）。同租户同 handlerCode 不允许并发 RUNNING（重复提交报 `DUPLICATE_RUNNING_TASK`），天然防手抖双击。

## 二、进度、结果与下载

`TaskContext` 是 handler 与任务中心交互的唯一句柄：

| 方法 | 用途 |
|---|---|
| `setTotal(int)` | 设置进度分母 |
| `updateProgress(percent, processed)` | 上报进度（写 Redis，内置 200ms 节流，放心高频调） |
| `recordSuccess(delta)` / `recordFailure(delta)` | 累加成功 / 失败计数 |
| `isCancelled()` | 长循环内周期检查，用户取消后应尽快 return |
| `setResult(Object)` | 结果落 `sys_task.result_data`（jsonb），POJO 自动转 Map |
| `params()` / `taskId()` / `tenantId()` | 读任务参数与元信息 |

任务状态机：`PENDING → RUNNING → COMPLETED / FAILED / CANCELLED`（另有取消中间态 `CANCELLING`）。前端统一从任务中心接口读列表 / 详情 / SSE 进度流 / 取消（`/api/v1/tasks` 一族），业务模块**不需要自建任务查询接口**。

**结果文件下载挂接**：handler 把产物经文件服务上传，在 `setResult` 里放 `fileId` 键，前端调 `GET /api/v1/tasks/{id}/download` 即可拿到 5 分钟签名 URL 的 302 跳转：

```java
FileUploadResult uploaded = fileService.uploadDirect(...);
ctx.setResult(Map.of("fileId", uploaded.fileId(), "fileName", fileName, "rows", rows));
```

任务终态默认自动发站内通知；handler 想自己发更贴切的通知（带跳转链接等），覆写 `suppressTerminalNotification()` 返回 `true`。

## 三、上下文传到异步线程

执行发生在 MQ 消费线程，请求线程的 ThreadLocal 全部不在。底座已处理大头：执行消息携带 `tenantId` 与 requestId，消费侧自动恢复 `TenantContext` 与请求链路上下文，handler 里的 SQL 照常被租户隔离拦截器保护。

但 **`UserContext` 不自动恢复**——数据权限要按"提交人"的范围过滤时，把操作者身份放进任务 params，执行侧重建后用 `UserContext.runAs` 包住查询（底座导出任务即此写法）。handler 内部再用 `@Async` 开子任务的话，底座的异步执行器已配好上下文透传装饰器，四类上下文（用户 / 租户 / 请求 / MDC）自动跟随。

## 四、发消息：领域事件

业务模块发消息优先走领域事件总线 `com.wensaas.core.api.event.DomainEventPublisher`：

```java
eventPublisher.publish("crm_demo.customer_created", Map.of("customerId", id));
```

它自动补全事件信封（tenantId、eventId、发生时间、requestId；结构即 `core-api` 的 `com.wensaas.core.api.event.EventEnvelope`，消费侧按它反序列化），投到统一事件 topic，webhook 订阅等下游能力随之可用（见 [Webhook 事件推送](11-Webhook事件推送.md)）。需要独立 topic 的专用链路（如自定义的高吞吐管道）才自己封装 `RocketMQClientTemplate`（RocketMQ 官方 v5 spring-boot starter 的生产者模板）——普通消息用 `asyncSendNormalMessage`，延时重投用 `syncSendDelayMessage`，全站不使用事务消息（一致性靠"本地表 + 事务后投递 + 补偿巡检"模式，见任务提交的写法）。

### 订阅别人的事件：声明式订阅（推荐）

消费平台或其他模块的事件**不必手写 MQ 消费者**：实现 `DomainEventHandler`（`core-api` 的 `event` 包）注册为 Bean，在描述符里声明订阅即可——

```java
@Component("crmDemoMemberDisabledHandler")
public class MemberDisabledHandler implements DomainEventHandler {
    @Override
    public void onEvent(EventEnvelope event) { /* TenantContext 已就位，按 event.payload() 处理 */ }
}

// BusinessModuleDescriptor：
@Override
public List<EventSubscription> eventSubscriptions() {
    return List.of(new EventSubscription("sys.member_disabled", "crmDemoMemberDisabledHandler"));
}
```

事件 code **精确匹配**；底座的订阅派发消费者负责恢复租户上下文、按 `(handler, eventId)` 幂等去重、异常时经 MQ 重投重做（实现自身按 `eventId` 幂等即可安全）。启动期校验 Bean 名存在且类型正确，写错即 fail-fast。底座自身发出的事件 code 见 `CoreEventTypes`（如 `sys.member_disabled` 成员停用）。仓内示例：`module-crm_demo` 的 `CrmDemoMemberDisabledHandler`——成员停用时统计名下客户并站内信提醒改派。

下面的手写消费者方式仍然可用，适合需要独立消费组 / 独立 topic / 自定义批量语义的场景。

## 五、写 MQ 消费者

RocketMQ 5 gRPC 客户端下，消费者 = 实现 `RocketMQListener` + `@RocketMQMessageListener` 注解 + 注册为 Bean：

```java
@RocketMQMessageListener(
        endpoints = "${rocketmq.push-consumer.endpoints:}",
        sslEnabled = false,                                   // 自建明文 Proxy 必须显式关 SSL
        topic = "${wen-saas-boot.crm-demo.event-topic:wen_event}",
        consumerGroup = "wen-saas-boot-crm-demo-event")
public class CrmDemoEventConsumer implements RocketMQListener {

    @Override
    public ConsumeResult consume(MessageView messageView) {
        String json = MqConsumeSupport.bodyOf(messageView);
        try {
            EventEnvelope event = JSON.parseObject(json, EventEnvelope.class);
            handle(event);                                    // 业务处理，包在幂等守卫里（见下）
            return ConsumeResult.SUCCESS;
        } catch (RuntimeException e) {
            return mqSupport.onConsumeFailure(GROUP, TOPIC, messageView, json, e);
        }
    }
}
```

`MqConsumeSupport` 与 `NonRetryableConsumeException` 都在 `com.wensaas.core.api.mq`：前者是底座装配好的 Bean，构造注入即得示例中的 `mqSupport`；`bodyOf` 是接口静态方法，直接类名调用。死信落库等内部实现业务模块不感知。

底座内置的全部消费者受总开关 `wen-saas-boot.mq.consumers-enabled`（默认 `true`）控制，用于"Web 节点只发、worker 节点消费"的收发分离部署（见部署指南）。自定义消费者建议在 Bean 装配处挂同一开关，跟随整机部署形态：

```java
@Bean
@ConditionalOnProperty(name = "wen-saas-boot.mq.consumers-enabled",
        havingValue = "true", matchIfMissing = true)
public CrmDemoEventConsumer crmDemoEventConsumer(...) { ... }
```

`ConsumeResult.SUCCESS` = ack 不再投递；`FAILURE` = 交 broker 稍后重投。**catch 块统一交给 `MqConsumeSupport.onConsumeFailure` 分流**，这是全站消费可靠性的核心约定：

| 情形 | 判定 | 结果 |
|---|---|---|
| 毒丸消息 | 异常链中含 `NonRetryableConsumeException` / JSON 解析失败 / `IllegalArgumentException` | 立即落死信表并 **ack**（重试也不会好，别空转） |
| 重试耗尽 | `messageView.getDeliveryAttempt() >= maxDeliveryAttempts`（默认 3，配置 `wen-saas-boot.mq.dead-letter.max-delivery-attempts`） | 落死信表并 **ack** |
| 瞬时故障 | 其余异常（网络 / DB 抖动） | 返回 `FAILURE`，broker 重投 |

死信不走 broker 的 `%DLQ%` topic，而是**在消费链路内用 `getDeliveryAttempt()` 主动判定、落库 `sys_mq_dead_letter`**——该表就是死信的唯一真相源，落库同时打告警指标（Micrometer 计数器，按消费组 / 来源打点），运维直接按表查询处置。业务上确定"这条消息永远处理不了"（目标实体已永久删除、语义非法）时主动抛 `NonRetryableConsumeException`；瞬时故障绝不要抛它。

## 六、幂等：at-least-once 下的硬要求

MQ 是至少一次投递，**消费副作用必须幂等**。底座提供 Redis 幂等守卫 `com.wensaas.core.api.idempotent.IdempotencyGuard`：

```java
boolean executed = idempotency.runOnce("crm-demo-event",        // scope：去重域
        event.eventId(),                                        // id：业务去重键
        Duration.ofMinutes(30),                                 // TTL：须大于单次处理最长耗时
        () -> handle(event));
if (!executed) log.info("skip duplicate eventId={}", event.eventId());
```

`runOnce` 语义：首次声明成功才执行；执行抛异常自动释放声明（允许 MQ 重投后重做），正常返回则声明保留。去重键选自然幂等键（taskId、eventId 等），TTL 太短会导致重复执行、太长无妨。Redis 幂等是第一道闸，关键路径再配一道 DB 级兜底（条件 UPDATE / 唯一约束），双层防重是底座内置消费者的标准姿势。

## 七、定时任务：ScheduledJob SPI

定时调度用应用内嵌的 Quartz（JDBC 集群存储，表在 PG 独立 `quartz` schema），没有独立调度中心。业务模块注册定时任务只需实现 `core-api` 的 `ScheduledJob` 接口并声明为 Bean，仓内示例是 `module-crm_demo` 的「阶段停留超期提醒」（扫描停留超过 N 天未推进的客户，按负责人聚合发站内信）：

```java
@Component
public class CrmDemoStageStaleJob implements ScheduledJob {
    @Override public String jobKey() { return "crm-demo-stage-stale"; }  // 全局唯一，兼作锁键
    @Override public String cron()   { return "0 0 9 * * ?"; }           // 默认 cron，可配置覆盖
    @Override public void execute()  { reminder.remindAll(); }
}
```

- **框架统一负责**：按 cron 触发、多实例单跑（Quartz 集群单节点触发 + 执行体外层 Redis 锁兜底，实现内不要再自己加锁）、停机漏跑恢复后补跑、异常兜底记日志。
- **cron 覆盖**：采用方可在 application.yml 用 `wen-saas-boot.jobs.cron.<jobKey>` 覆盖默认值；`wen-saas-boot.jobs.enabled=false` 整体关闭调度。
- **调度与逻辑解耦**：`ScheduledJob` 实现只做委托，真正的扫描逻辑放在始终装配的普通组件（示例里的 `CrmDemoStageStaleReminder`），关闭调度的环境可直接调用、也方便单测。
- **跨租户遍历**：job 线程没有租户上下文，用 `TenantQueryService.activeTenantIds()` 拿正常状态租户列表，逐个 `TenantContext.runAs(tenantId, ...)` 后再走模块自己的 Mapper（TenantLine 自动隔离）。
- **可配阈值**：模块可声明自己的 `@ConfigurationProperties`（示例前缀 `wen-saas-boot.crm-demo`），采用方在 application.yml 覆盖。

## 八、接入检查清单

1. 实现 `TaskHandler`（`@Component`），`handlerCode` 带模块命名空间前缀；
2. 模块入口 `taskHandlers()` 声明 `TaskHandlerDef`；
3. 提交走 `TaskService.submit`，参数只放可 JSON 序列化的内容；
4. handler 内：设 total、报进度、查 `isCancelled()`、结果放 `setResult`（有产物文件带 `fileId`）；
5. 消费者：`RocketMQListener` + `@RocketMQMessageListener`（Bean 注册），catch 统一走 `MqConsumeSupport.onConsumeFailure`，永久性失败抛 `NonRetryableConsumeException`；
6. 副作用包进 `IdempotencyGuard.runOnce`，TTL 大于最长处理时长；
7. 验证：提交任务看 SSE 进度、取消一次、制造一条毒丸消息确认进 `sys_mq_dead_letter` 而不是无限重投。
