# 自定义字段前端接入

业务对象接好自定义字段框架后，租户可以自助给它加字段（文本/长文本/数字/布尔/日期/枚举/引用七种类型）。前端接入点固定四个：**筛选、列表列、表单、详情**，每个接入点都有现成组件，本篇是可直接抄的清单。完整参考实现是客户管理 Demo（`apps/tenant-web/src/features/crmdemo/`）。

## 一、前置条件（后端就绪才能接）

- 业务对象已在后端注册了自定义字段 `objectCode`（如 `crm_demo.customer`）：实体表带 `extra jsonb` 列、实体标了对应注解。
- 业务的列表/创建/更新接口已接好两段数据：请求体的 `custom`（提交的自定义字段值）与响应体的 `extra`（字段值视图，enum/ref 类型附带 `{fieldCode}__label` 衍生键，值为人类可读名）。前端组件只负责渲染/收集，不替接口造数据形状。
- 若业务对象会被 `ref` 类型字段关联（"选择关联到 xx 的一条实例"），被关联对象需在后端注册名称反查；否则 `ref` 字段在列表/详情只能显示裸 id。

## 二、现成组件 / Hook 一览

全部在 `apps/tenant-web/src/features/customfield/`，跨业务复用，**不要在业务 feature 目录重新实现**：

| 名称 | 用途 | 挂载位置 |
|---|---|---|
| `useCfFields(objectCode)` | 拉字段定义元数据（`type` / `indexed` / `refDictCode` / `refObjectCode`...） | 下列组件内部已调，业务代码一般不直接用 |
| `useCustomFieldColumns<T>(objectCode)` | 字段定义 → 列表列（`PrefColumn[]`） | 列表页，拼在标准列后面 |
| `CustomFieldFilters` | 已索引字段 → 筛选控件（按类型出对应控件） | 筛选区，标准筛选项后面 |
| `CustomFieldFormFields` | 字段定义 → 动态表单段 | 新增/编辑表单内，标准字段后面 |
| `CustomFieldDescriptions` | 字段定义 + `extra` → 详情"扩展信息"区块 | 详情页/抽屉 |
| `EntityRefPicker` | 通用"按名称搜实例"选择器（`ref` 字段控件；也可单独用，见 §六） | 表单内由 `CustomFieldFormFields` 自动接好 |
| `DictEnumSelect` | `enum` 字段的字典下拉（按 `refDictCode`） | 由 `CustomFieldFormFields` / `CustomFieldFilters` 内部自动接好 |

## 三、列表页接入（4 步）

```tsx
// 1. 列：拼进标准列后面，一起进列偏好（用户可隐藏/拖序自定义字段列，零额外处理）
const cfCols = useCustomFieldColumns<CrmCustomerListItem>(CRM_CUSTOMER_OBJECT);
const allColumns = useMemo(() => [...standardCols, ...cfCols], [standardCols, cfCols]);
const { columns } = useColumnPreference(viewKey, allColumns);

// 2. 筛选区：草稿/已提交两态，点「搜索」才生效
const [cfDraft, setCfDraft] = useState<Record<string, string>>({});
const [cfEquals, setCfEquals] = useState<Record<string, string>>({});
<CustomFieldFilters objectCode={CRM_CUSTOMER_OBJECT} value={cfDraft} onChange={setCfDraft} />;
const applySearch = () => { /* ...其它筛选... */ setCfEquals(cfDraft); };

// 3. 接列表查询：cfEquals 作为 query hook 的第二个参数单独传
const listQuery = useCustomerList(query, cfEquals);
```

要点：

- 只有**已索引**的字段会出现在筛选区；无可筛字段时 `CustomFieldFilters` 直接返回 `null`，业务代码不用判断"要不要渲染这一段"。
- `cfEquals` 的 key 就是字段编码（`cf_xxx` 形式），API 层把它摊进请求参数、后端按 `cf_` 前缀识别为自定义字段等值筛选——所以别把它混进标准查询对象（参考 `packages/api-client/src/crmDemo.ts` 的 `list(query, cfEquals)` 签名）。
- 非索引字段查询会被后端拒绝，这是护栏：非索引字段只在表单/详情可见可改，前端不需要也不应该绕过。

## 四、表单（新增/编辑）接入

```tsx
<Form form={form} layout="vertical">
  <Form.Item name="name" label="客户名称" rules={[{ required: true, message: '必填' }]}>
    <Input />
  </Form.Item>
  <CustomFieldFormFields
    objectCode={CRM_CUSTOMER_OBJECT}
    refLabels={refLabels(detailQuery.data?.extra)}   // 编辑场景传；新增可省
  />
</Form>
```

- 每个字段挂在 `Form.Item name={['custom', fieldCode]}` 下，`form.validateFields()` 拿到的 `values.custom` 整段就是请求体的 `custom`，不用自己拼字段名。
- **编辑回显要剥 `__label`**：详情 `extra` 里混着 enum/ref 的 `{fieldCode}__label` 衍生键，回填前剥掉，否则会把 `__label` 当字段名一起提交：

  ```ts
  function rawCustom(extra: Record<string, unknown> | null | undefined) {
    const out: Record<string, unknown> = {};
    for (const [k, v] of Object.entries(extra ?? {})) {
      if (!k.endsWith('__label')) out[k] = v;
    }
    return out;
  }
  form.setFieldsValue({ name: d.name, custom: rawCustom(d.extra) });
  ```

- **ref 字段回显名字而非 id**：把 `__label` 键抽成 `fieldCode → 展示名` 映射传给 `refLabels` prop，`EntityRefPicker` 无需重新搜索即可显示名字（抽取函数见 `features/crmdemo/CustomerFormModal.tsx` 的 `refLabels`）。
- **提交前剔除空值**：用户清空可选字段时把 key 整个删掉，不要传 `''` / `null`，否则会触发 enum/ref 的服务端校验（"必须是合法字典项/合法 id"）：

  ```ts
  function cleanCustom(c: Record<string, unknown> | undefined) {
    if (!c) return undefined;
    const out: Record<string, unknown> = {};
    for (const [k, v] of Object.entries(c)) {
      if (v === '' || v === null || v === undefined) continue;
      out[k] = v;
    }
    return Object.keys(out).length ? out : undefined;
  }
  ```

完整写法：`apps/tenant-web/src/features/crmdemo/CustomerFormModal.tsx`。

## 五、详情页接入（1 行）

```tsx
<CustomFieldDescriptions objectCode={CRM_CUSTOMER_OBJECT} extra={detail.data?.extra} />
```

自动渲染"扩展信息" `Descriptions` 区块：enum/ref 优先显示 `__label`，bool 渲染是/否，空值显示 `-`；对象没有自定义字段时返回 `null`，不用外包判断。

## 六、EntityRefPicker：不止 ref 字段能用

表单里的 `ref` 字段控件就是 `EntityRefPicker`（`objectCode={字段的 refObjectCode}`），由 `CustomFieldFormFields` 内置接好。但**凡是"选人 / 选部门 / 选关联实例"的筛选或表单字段**——不限于自定义字段场景，比如列表页的"归属人"筛选——都应直接复用它：

```tsx
<EntityRefPicker
  objectCode="sys.user"        // 内建类型；也可以是已注册反查的业务对象
  value={ownerDraft}           // 只存 id（string）
  onChange={setOwnerDraft}
/>
```

- **占位符与下拉主显自动生成**：组件按该对象在后端声明的可搜字段拼占位符（如"输入姓名搜索"），下拉主行显主字段、淡色显次字段，接入者不写任何分支。搜索是单关键字 OR 命中全部可搜字段。
- **底层是通用实体反查端点**（`/api/v1/base/entity-lookup/{type}/search`），登录即可访问、不挂业务权限点——它只回 `{id, 展示名}`，本就设计给多个无关消费者共用。**不要**图省事改调挂着具体业务权限的列表/搜索接口做这类筛选：有你页面权限的角色未必有那个权限，控件会对部分角色直接 403。
- 筛选（草稿态）用法不需要维护 `{id, label}` 对象，展示名靠当次搜索结果撑住，重置时清空 value 即可；只有表单编辑回显已知 id 时才需要传 `label` prop。

内建可直接搜的 `objectCode`：`sys.user`（成员，按姓名）、`sys.dept`（部门，按名称）、`sys.role`（角色，按名称/编码；仅供搜索选择，角色不作 ref 字段的关联目标）。业务对象在后端注册名称反查并开启租户可搜后，前端零代码即可被搜到、被 ref 字段关联。
