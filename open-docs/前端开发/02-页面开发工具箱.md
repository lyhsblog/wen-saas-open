# 页面开发工具箱

写业务页面之前先过一遍这篇：底座已经提供了哪些可复用件、数据层怎么写、哪些安全规约是硬约束。原则是**类型签名 + JSDoc 是权威**，本篇只回答"有什么、用哪个、怎么组合"；端到端范例看 `apps/tenant-web/src/features/dict/`（标准 CRUD 模块）与 `apps/tenant-web/src/features/crmdemo/`（含自定义字段/列偏好/数据权限）。

## 一、shared-ui 组件速览（`@wen-saas/shared-ui`）

| 导出 | 用途 |
|---|---|
| `AppShell` / `SidebarMenu` | 应用壳与侧栏；菜单树吃后端下发，业务模块不用碰 |
| `PageHeader` | 面包屑 + 标题 + 操作区 |
| `MasterDetail` | 左列表右详情壳（字典、角色等同页详情场景） |
| `DataTable<T>` | 表格：title/toolbar 槽 + 密度 + 空态 + onRowClick + 默认分页 |
| `WizardModal` | 多步向导；步级 `onBeforeNext` 异步校验可阻断下一步 |
| `DangerConfirm` | 敏感操作二次确认；警示框 + 可选"输入确认文本" |
| `ErrorState` + `Forbidden403Page` / `NotFound404Page` / `Conflict409Page` / `ServerError5xxPage` | 错误页；业务方不要手写 403/404/409/5xx |
| `TaskCenter` / `TaskStatusTag` | 异步任务列表壳；filter / items 由调用方持有 |
| `FilePickerUploader` | 拖拽/选择 + 上传队列；**不绑网络**，上传逻辑由调用方注入 |
| `CopyableText` / `StatusPill` | 可复制文本、状态胶囊 |
| `useListQuery` | 列表页"筛选 + 分页"状态 hook：改筛选自动回第 1 页，`query` 可直接当 queryKey 与请求参数 |
| `resolveColumns` / `PrefColumn` / `ColumnPref` / `ColumnPanel` | 列偏好纯函数层（见 §四） |
| `TabsBar` / `KeepAlivePanes` / `useTabsController` 等 | 多页签壳与保活容器（入口 app 已装配，业务页无感） |
| `formatDateTime` / `formatDate` | 统一时区的时间格式化 |

## 二、api-client 用法（`@wen-saas/api-client`）

**业务代码不直接 import axios、不手写 URL 字符串。** 统一路径：

1. 每个领域一个 endpoint helper 工厂：`export function xxxApi(http: HttpClient) { ... }`（参考 `packages/api-client/src/dict.ts`）。请求/响应类型随 helper 一起导出。
2. app 内建一个 thin shim 注入全局 http 实例：`export const dictApi = dictAdminApi(http);`（参考 `apps/tenant-web/src/features/dict/dictApi.ts`）。
3. 页面用 TanStack Query 包 hook：`useQuery({ queryKey, queryFn: () => dictApi.listGroups() })`；**不要 useEffect + useState 拉数据**。

错误模型——所有请求 reject 出来的都是 `ApiError`：

- `err.status` + 判定方法 `isValidation()` / `isConflict()` / `isForbidden()` / `isNetwork()` 等；
- `err.fieldErrors`：422 时后端字段级错误的 `field -> message` 映射；
- `describeApiError(err, fallback?)`：统一 toast 文案（5xx 时附请求编号 Request-ID，便于报障定位）；
- `applyApiErrorToForm(err, setError)`：把 422 字段错误挂到 react-hook-form 内联展示，返回 `true` 表示已消化、调用方跳过 toast。

表单的标准分工：Modal 内 `applyApiErrorToForm` 处理 422 内联 + 非 422 自己 toast；页面层只跑成功路径。

**雪花 id 一律 string。** 后端 Long 型主键在 JSON 中序列化为带引号字符串，前端类型必须用 `string` 承接（包括分页 `total` 这类 long），不要转 `number`——会丢精度导致查错记录。api-client 里所有 id 字段的既有类型都是范例。

## 三、字典

- **管理侧**：字典分组与字典项的增删改查走 `dictAdminApi(http)`，页面范例即 `features/dict/`。业务模块要预置字典分组，在后端模块描述符里声明，不在前端造。
- **消费侧**：表单/筛选里要出"某字典分组的下拉"，直接用 `apps/tenant-web/src/features/customfield/DictEnumSelect.tsx` 的 `<DictEnumSelect dictCode="..." />`，不要自己拉字典项拼 options。

## 四、列表列偏好（用户级列设置）

让用户能对列表隐藏列/调列序，接入三步（范例：`features/crmdemo/CustomersPage.tsx`）：

```tsx
// 1. 列声明用 PrefColumn（antd ColumnType + 偏好元信息）
const allColumns: PrefColumn<Row>[] = useMemo(() => [
  { key: 'name', title: '名称', pin: 'left' },        // pin 列固定，不参与排序/显隐
  { key: 'status', title: '状态', render: ... },
  { key: 'actions', title: '操作', pin: 'right', render: ... },
], [...]);

// 2. 绑定用户偏好（viewKey 全局唯一，如 'crm_demo.customers'）
const { columns, panel, isCustomized, saving, apply, reset } =
  useColumnPreference(viewKey, allColumns);

// 3. columns 直接喂 DataTable；panel + apply/reset 喂"列设置"弹层
```

`useColumnPreference` 在 `apps/tenant-web/src/features/columnpref/useColumnPreference.ts`：内部走 `viewPrefApi` 持久化到用户级偏好、`resolveColumns` 合成最终列。要点：`key` 必须稳定唯一（持久化用）；`title` 是 ReactNode 时补 `settingLabel` 纯文本；`allColumns` 在调用方 `useMemo` 稳定。自定义字段列（`useCustomFieldColumns` 产出）同样是 `PrefColumn`，拼进数组即一起参与偏好。

## 五、安全规约（业务方必须遵守）

**敏感字段脱敏**

- 手机/邮箱等联系方式在通用查询接口（列表/详情）里**一律是掩码**（如 `138****0001`），这是后端职责；前端不做"补救式脱敏"，也**不得**试图从别的接口拼出明文。
- 需要看明文时调专用 reveal 端点（形如 `GET .../{id}/contact`），它带权限门控 + 审计；入口按钮用 `useHasPermission` 前置隐藏（如 `org.member.contact.reveal`）。
- **编辑守卫**：编辑表单回填的是掩码占位。真实手机/邮箱不含 `*`，故"值含 `*`"即掩码——编辑态要放行含 `*` 的占位通过校验（提示"保留原值表示不变"），由后端识别"提交值 == 掩码"视为未修改。不要在前端把掩码值当新值提交逻辑里特殊处理掉以外的花样。

**XSS**

- 全前端零 `dangerouslySetInnerHTML` / `innerHTML` / `outerHTML` / `insertAdjacentHTML`，eslint 已把这些 sink 设为 error，提交期拦截。
- 未来确需渲染富文本：先经 DOMPurify 白名单净化，再在该行单独 `eslint-disable-next-line` 并注释净化来源；禁止整文件关规则。

**CSP**

- 三端 dev server 均下发 CSP 头，基线 `default-src 'self'`；dev 策略为配合 Vite HMR 与 antd CSS-in-JS 放行了 `unsafe-inline` / `unsafe-eval`，个别应用另有显式域名白名单（见各 app `vite.config.ts` 的 `DEV_CSP`）。生产的严格策略由网关统一下发，不依赖 dev 配置。
- 其中 tenant-web dev 对若干 CDN 域（`script-src`）与 `https:` 外联（`connect-src`）的放行，是为内置的 page-agent 体验性示例临时开的口子——该示例未正式集成，这份放行不代表底座的网络边界约定，业务开发不应依赖 dev CSP 的这部分宽松放行。
- 引入白名单外的第三方 CDN 脚本、绕过 dev proxy 直连未放行的外部地址，会在 dev 控制台报 CSP 违规——这是有意设计，别用继续放宽 dev CSP 的方式"修"它；后端请求一律走 dev proxy（`/api`）。

**水印与其他**

- 全页水印（代登录标识、防截屏溯源）由 `@wen-saas/permissions` 的 `WatermarkLayer` 在 AppShell 层统一渲染。新的全页水印需求扩它的分支，**不要**在各 feature 页面自己包 antd `Watermark`。
- 权限门禁组件（`PermissionGate` / `PackageGate` / `useIsReadonly` / `ReadonlyButton`）只是体验控制，后端在 API 层重新校验——不要因为"后端会拦"就省掉前端门禁，也不要以为加了前端门禁就安全。
- Secret/密钥类值仅创建时一次性展示；导出动作走任务中心与审批链路，不做前端"直接拼 URL 下载"的旁路。

## 六、反模式清单

```
❌ 直接 import axios / 手写 fetch          ✅ @wen-saas/api-client 的 HttpClient + endpoint helper
❌ 组件里硬编码后端 URL 字符串              ✅ endpoint helper 统一收口
❌ useEffect + useState 拉数据              ✅ TanStack Query
❌ useEffect 里反向同步 state               ✅ 派生计算（参考 features/dict/DictPage.tsx 的 selectedCode 模式）
❌ id / total 用 number 承接                ✅ 雪花 id 与 long 一律 string
❌ Modal onOk 自己 try-catch 逐个 toast      ✅ applyApiErrorToForm(422 内联) + describeApiError(其余)
❌ 业务按钮裸渲染                           ✅ 包 PermissionGate(permission)
❌ 把能力过滤逻辑塞进 router 表              ✅ 路由全量注册，element 侧 PermissionGate/PackageGate 拦截
❌ 手写 403/404/409/5xx 页面                ✅ shared-ui 错误页四件套
❌ AntD Form 真表单与 react-hook-form 共存   ✅ <Form component="div"> 仅做视觉容器
❌ FilePickerUploader 里塞上传请求           ✅ 组件不绑网络，onSelect 后调用方自决上传方式
❌ 自己拉字典项拼 Select options             ✅ DictEnumSelect
❌ 改前端 manifest 想给模块加菜单            ✅ 菜单权威在后端，走运营端菜单管理
❌ dangerouslySetInnerHTML 渲染任何外部内容   ✅ 见 §五 XSS
```
